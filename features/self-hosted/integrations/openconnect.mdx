<Note>
  OpenConnect is in preview. Contact [support](/support) to confirm it is enabled for your organization and release.
</Note>

## Prerequisites

Complete the [shared prerequisites](/features/self-hosted/integrations/overview). Prepare a supported VPN gateway, credentials approved for agent access, and outbound access from sandboxes to the gateway. Review the [supported VPN protocols](/integrations/openconnect#supported-vpns).

## Connect the VPN

1. Open **Settings → Integrations** on your instance and install OpenConnect.
2. Enter a connection name, VPN protocol, gateway hostname or IP, username, and password.
3. Save the connection. If you need database access, add a [Postgres connection](/features/self-hosted/integrations/postgres) using the database's private address.

No instance-level OAuth application is required. Interactive MFA prompts are not supported; agree on an approved authentication approach with your security team rather than disabling MFA broadly.

## Verify

In a new session, ask the agent to connect to the VPN and reach a test internal service. The tunnel is established on demand and lasts for that session, not across all future sessions.

If login succeeds but access fails, check VPN routes, DNS, and the account's network policy. A working VPN on the host VM alone does not prove sandbox connectivity. See [OpenConnect usage](/integrations/openconnect).
